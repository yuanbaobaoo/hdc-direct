# hdc-direct 编码规范

> 本规范派生自 `/Users/Shared/codes/work/ai-context/coding-rules.md` 中与
> TypeScript / JavaScript 相关的条款，并结合本项目（Node CLI + 零运行时依赖 +
> 二进制协议实现）的实际约束。**与上游规范冲突时以本文为准**，但新增条款需
> 说明理由。
>
> 所有回复与代码注释使用**中文**，标识符命名使用**英文**。

---

## 1. 格式（强制）

### 1.1 缩进

- TypeScript / JavaScript 统一 **4 个空格缩进**，禁止 2 空格或 Tab；
- `package.json`、`tsconfig.json` 等 JSON 配置用 2 空格（工具约定）；
- Markdown 列表内代码块跟随所在层级，不做额外强制。

### 1.2 换行与空行

- 单行 `const` / `let` 声明之间不空行；多行声明（对象、模板、多行泛型）前后必须空行；
- 函数之间空一行；类成员方法之间空一行。

---

## 2. 注释（强制）

| 目标 | 格式 | 要求 |
| --- | --- | --- |
| 模块级 `const` / `let` | `//` 单行注释 | **必须**每个都加，说明用途而非复述字面值 |
| 函数内 `const` / `let` | `//` 单行注释 | 非自明变量必须加；类型明确的短生命周期临时值与循环计数器可省略 |
| 顶层 `function` | `/** */` JSDoc | `/**` 后必须换行，每行以 `*` 起头 |
| 类的方法 | `/** */` JSDoc | 公开方法必须写；参数含 `@param`，返回值含 `@returns` |
| 接口 / 类型字段 | `//` 或 `/** */` | 语义不自明时必写 |
| 协议常量 | `//` 单行 | 必须注明协议出处（源码文件或抓包事实） |

禁止：

- `/** 获取列表 */` 这类单行 JSDoc（`/**` 后必须换行）；
- 用 JSDoc 注释普通变量；
- 注释与代码不同步——改协议行为必须同步改注释。

---

## 3. 函数与声明

- 顶层独立函数一律 `function` 声明，禁止 `const fn = () => {}`；
- 函数内部回调（`map` / `filter` / `setTimeout` / 事件处理）一律箭头函数；
- 类方法用标准语法，不用类字段箭头函数（除非需要绑定 `this` 的事件回调）；
- 导出符号显式标注返回类型；参数类型必填，不依赖推断。

---

## 4. 异步（强制）

- 一律 `async/await` + `try/catch`，**禁止** `.then()/.catch()` 链式写法；
- CLI 入口使用 `async function main()` 包裹，返回值作为进程退出码；
- 异步超时必须显式设置（本项目默认 60s，环境变量 `HDC_SHELL_TIMEOUT` 可覆盖），
  不允许无限等待；
- 资源（socket）必须在 `finally` 或显式 `close()` 中释放。

---

## 5. 常量与魔法值

- 魔法字符串 / 数字抽为 `const` 常量，命名 `UPPER_SNAKE_CASE`；
- 协议层常量（命令字、认证类型、帧标志）必须集中在 `src/proto.ts`，
  其他模块只引用不重复定义；
- 命令行关键字（子命令、选项名）在 CLI 层以常量或集中分支表达，
  禁止散落多处的重复字面量；
- 路径拼接统一用 `node:path`，禁止手写分隔符。

---

## 6. 类型

- `strict: true` 全开；`tsconfig.json` 的 `strict` 系列开关不得放宽；
- 禁止 `any`；外部数据用 `unknown` 并在使用前收窄；
- 跨模块边界（`src/index.ts` 导出）必须给出完整类型与 `.d.ts` 产物；
- 禁止使用非空断言 `!` 掩盖可能为空的路径，除非紧随其后的判断可证明非空。

---

## 7. 模块与依赖

- 纯 ESM，`module` / `moduleResolution` 均为 `NodeNext`，相对导入必须带 `.js` 后缀；
- **零运行时依赖**：`dependencies` 必须为空，只用 Node 内置模块；
  devDependencies 仅允许类型与构建工具（`typescript`、`@types/node`）；
- 新增依赖需在 PR/提交说明中给出理由与体积影响；
- 文件职责单一：`proto`（编解码）/ `auth`（密钥）/ `session`（会话）/
  `targets`（状态）/ `cli`（命令面）/ `index`（导出），
  禁止把协议细节泄漏到 CLI 层。

---

## 8. 协议实现约束（本项目特有）

- 协议字节行为以 `test/proto.golden.test.ts` 的黄金用例为准，**修改编码器必须
  保持这些用例通过**；新增行为需同时补充抓包证据（注释注明日期与 hdcd 版本）；
- 每条非显然的协议选择都要有注释解释「为什么」，并注明依据
  （源码文件 / 抓包行为 / 实测结论）；
- 涉及真机实测的结论写入 `README.md` 的「版本矩阵」与「部署到鸿蒙真机」；
- 禁止在协议层加入针对特定设备型号的分支（版本差异用能力探测或日志说明）。

---

## 9. 测试

- 使用 `node --test`，测试文件放 `test/`，命名 `*.test.ts`；
- 协议、编码、帧解析必须有单元测试；涉及设备的集成验证写进 README 记录，
  不在 CI 中依赖真机；
- 测试不引入第三方断言库（用 `node:assert/strict`）；
- 提交前必须通过：`npm run typecheck`、`npm test`。

---

## 10. 构建与发布

- 只构建当前项目，不做全量构建；
- 发布流程：`npm run typecheck` → `npm test` → `npm run pack:release`；
- 发布资产命名固定为 `hdc-direct-<version>.tar.gz` / `.sha256` / `.json`，
  下游（如 zcode-ohos）按此约定拉取，改名需同步通知下游。

---

## 11. 修改代码约束

1. 优先最小改动；
2. 不影响已有功能；
3. 不修改无关文件；
4. 修改前说明影响范围。

---

## 12. Git 操作（强制）

- **未经允许禁止自行创建分支**（`git checkout -b` / `git switch -c`）；
- **未经允许禁止自行提交或推送**（`git commit` / `git push`）；
- 提交前需说明改动范围与验证结果，等待确认后再执行。

---

## 13. 提交信息格式

```
<type>(<scope>): <中文摘要>

<变更说明：做了什么、为什么>
<验证结果：执行的命令与真实输出结论>
```

`type` 取值：`feat` / `fix` / `refactor` / `docs` / `test` / `chore` / `build` / `ci`。
摘要使用中文，祈使句，不超过 50 字。
